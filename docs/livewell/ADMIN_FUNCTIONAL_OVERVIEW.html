4. Care delivery

4.1 Clients — /livewell/customers

Care spine Lead → convert → assess → publish score to family.

  • Create / manage elder prospects and clients (elders + prospects pipeline).
  • Start or open home assessments; link assessment to client.
  • Republish Independence Score™ / living plan to the family portal.
  • Admin danger zone: permanent delete of client / lead / assessment (admin roles).

APIs: /api/v1/elders, /api/v1/prospects/elders, /api/v1/home-safety/assessments

4.2 Assessments — /livewell (assessor shell)

Ops nav “Assessments” opens the assessor PWA list, not an ops-chrome page. Wizard: resident intake → scored sections → photos → review (score, improvement plan, quote).

  • Rubric ratings: Excellent / Acceptable / Unsafe / N/A → SafeHome Score™ / Independence Score™.
  • Conditional logic hides irrelevant items from resident profile.
  • Photos, AI visualization jobs, signed documents, recommendation chat.

APIs: /api/v1/home-safety/assessments, photos, signed-docs, recommendation-chat, AI

4.3 Visits & check-ins — /livewell/visits

Ongoing care After enrollment, trend comes from visits — not repeated full assessments.

ScoreSourceCadence
Independence Score™ Home assessment publish Intake (rare re-assess)
Care stability score Structured Care Manager visits Every completed visit (baseline = 50)
  • Baseline visit: Observe/Ask protocol; type forced to Baseline profile; score 50; optional family message.
  • Later check-ins: Multiple-choice scoring → GREEN / YELLOW / RED “Mom is OK” status; history for family sparkline.
  • Also: living plan items, family service request triage, installer partner pick.

APIs: /api/v1/home-safety/visits, /api/v1/home-safety/care/*

4.4 Session activity — /livewell/activity

  • Accordion timeline of staff / assessor / family / system sessions.
  • Meaningful user actions + optional verbose API hydration.
  • IoT ingest (SOS) appears under Actor → System; expand Details (JSON) for raw_payload.
  • Verbose: set ACTIVITY_LOG_MODE=verbose on API .env.

APIs: /api/v1/activity/sessions (WRITE_ROLES)

5. Assessments & commercial pipeline

Assessment finding (Unsafe / Acceptable) ↓ Solution library (SH-*) ↓ Product catalog (SKU via solution_ids) ↓ Pricing engine (margin, labor, travel, GST) ↓ Customer quote (assess review + report) ↓ [Planned] Approval → work order → invoice

Admin configures rubric / solutions / catalog / pricing; assessors consume them in the wizard. Showcase packages are family-facing via public catalog API.

8.2 Wearables (B7 / MG7) — /livewell/iot-devices pilot

Register Minew (or compatible) gateway + SOS band bound to an elder.

  • Register kit: creates hub MQTT user/topic + band MAC → elder; shows MinewLink settings.
  • Update MAC: replace band for same elder without new hub.
  • Ingestor polls GET /api/v1/iot/device-map; SOS → family critical alert + Session activity (System).
  • Hardware config still in vendor apps (BeaconSET / MinewLink); not in LiveWell UI.
Band --BLE--> Gateway --MQTT/TLS:8883--> Mosquitto --> safehomeops-iot-ingestor --HTTP--> POST /api/v1/iot/events --> Family alert + care-hub incident

APIs: /api/v1/iot/{hubs,devices,register-kit,devices/mac,device-map,events} (events use X-IoT-Ingest-Key, not staff JWT)

Full managed-safety product (escalation worker, multi-contact ack, offline monitoring) is gated behind initial hardware validation — see docs/livewell/IOT_PILOT_IMPLEMENTATION.md. Do not build escalation in FastAPI background tasks.

10. Family touchpoints (what ops enables)

Family app is separate; ops staff enable it through clients & visits:

  • Publish assessment score / plan after conversion.
  • Visit baselines & check-ins feed care stability card + trend.
  • Service requests from family appear for staff triage on Visits.
  • Wearable SOS → family Alerts (critical).
  • Emergency contacts today: thin elder fields; multi-contact OTP is post-validation pilot work.

12. End-to-end flows (admin mental model)

A. New home safety customer

  1. Ops: create lead / client on Clients.
  2. Assessor: complete assessment on /livewell → score + plan + quote.
  3. Ops: convert / link / publish to family.
  4. Care manager: baseline visit on Visits, then periodic check-ins.
  5. Family: sees Independence Score™ + care stability trend + alerts.

B. Configure commercial content

  1. Tenant admin: edit rubric / solutions / catalog / pricing or import master Excel.
  2. Master data: stage → approve → seed tenant overrides.
  3. Assessors immediately consume updated matching / quote math.

C. Wearable SOS (pilot)

  1. Admin: Wearables → register kit (MAC + MQTT credentials).
  2. Field: configure gateway with shown MQTTS host/port/user/topic.
  3. Band SOS → Mosquitto → ingestor → API → family critical alert.
  4. Ops: confirm in Session activity (System) and family Alerts.

14. Known gaps / pilot notes

  • IoT Phase 1: registry + SOS ingest + in-app alert. No SMS/voice escalation ladder, no installer PWA, no relational safety_incident ack yet.
  • Escalation rule: use durable Postgres outbox + worker — never FastAPI in-process timers.
  • Care manager vs catalog: CM does not see Catalog/Platform in nav (admins configure commercial content).
  • Assessments dual shell: intentional — field chrome differs from ops chrome.
  • Quote → work order / invoice: planned (Phase D+), not shipped.
  • AI default: may run as local stub without GPU provider.
